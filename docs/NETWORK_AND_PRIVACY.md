# Lumisense: сеть, приватность и журналы

Этот документ описывает, когда Lumisense обращается к внешним сервисам, какие данные участвуют в запросе и как пользователь может управлять соответствующими функциями.

## Внешние обращения

| Функция | Сервис | Когда выполняется | Данные запроса | Управление пользователем |
|---|---|---|---|---|
| Проверка обновлений | GitHub Releases API | При ручной проверке и, если включено, при старте | Версия приложения, обычные HTTPS-заголовки клиента | Проверка обновлений отключается в настройках; установка запускается только после действия пользователя. |
| Скачивание обновления | GitHub Releases | После подтверждения обновления | HTTPS-запрос к asset релиза | Можно выбрать прямой GitHub или явно настроенное зеркало; SHA-256 установщика проверяется до запуска. |
| Зеркала обновлений | gh-proxy.org, v4/v6/cdn.gh-proxy.org | Только после явного выбора источника в настройках | URL GitHub release asset | Значение по умолчанию — прямой GitHub; использование зеркала добровольно. |
| Автопоиск текста | LRCLIB | Когда для трека нет локального/закэшированного текста и включён поиск | Название композиции и исполнитель | Текст можно искать вручную, вставить локально или использовать без сетевого поиска. |
| Открытие поиска Genius | Genius | Только после нажатия пользователем команды открытия поиска | Поисковый запрос в URL браузера | Запрос открывается в браузере; Lumisense не передаёт результат обратно автоматически. |
| Поиск обложки | iTunes Search, Deezer Search | Только в окне поиска обложки после запуска пользователем | Поисковая строка | Результат выбирается пользователем перед сохранением. |
| Аватар разработчика | GitHub avatar | При показе карточки разработчика | Обычный HTTPS-запрос изображения | Не содержит данные музыкальной библиотеки или трека. |
| Discord Rich Presence | Локальный Discord IPC | Если пользователь подключил Discord | Метаданные текущего трека в локальный клиент Discord | Интеграция и параметры приватности настраиваются отдельно. |

Ссылки на GitHub, Telegram и страницы релизов открываются только по действию пользователя во внешнем браузере.

## Локальные данные и журналы

Настройки, плейлисты, кэш обложек, кэш текста и журналы хранятся локально в папке данных приложения. Lumisense не отправляет логи автоматически.

Вставленные вручную тексты песен хранятся в отдельном локальном кэше с SHA-256-именами файлов: исходный путь к аудиофайлу в текст не записывается. Кэш ограничен 200 записями и 32 MiB, неиспользуемые записи удаляются через 180 дней; его можно очистить со страницы «Профиль». Это не удаляет `.lrc`/`.txt` рядом с аудиофайлами и тексты в тегах.

Перед обычным или полным сбросом Lumisense создаёт до трёх локальных точек восстановления полного `settings.json`. Они могут содержать плейлист, избранное, статистику и пресеты, не экспортируются и не передаются по сети. Последнюю корректную точку можно вернуть со страницы «Профиль».

При записи общего журнала Lumisense маскирует имя пользователя в абсолютных путях вида `C:\Users\<user>\…`, скрывает UNC-сетевые пути и обрезает чрезмерно длинные сообщения. В папке журналов хранится не более 50 файлов и не более 16 MiB суммарно; отдельный файл ротируется после 1 MiB.

> Лог может по-прежнему содержать технические сведения: тип ошибки, имя аудиофайла без личного сегмента пути, состояние устройства и сетевой статус. Перед публикацией лога в открытом issue рекомендуется просмотреть его содержимое.

## Проверка обновлений

Lumisense принимает обновление только из доверенных HTTPS-адресов и проверяет SHA-256 скачанного установщика с digest, опубликованным в GitHub Release. Если digest отсутствует или не совпадает, установщик не запускается.

Для выпуска релиза GitHub Actions дополнительно проверяет, что опубликован единственный непустой `Lumisense_Setup.exe` и GitHub API возвращает корректный `sha256:` digest для asset.

## Обратная связь

Если вы обнаружили ошибку в описании обращений или хотите ограничить конкретную интеграцию, создайте issue в репозитории Lumisense и укажите версию приложения.
